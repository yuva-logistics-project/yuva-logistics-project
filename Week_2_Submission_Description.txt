This report documents a reproducible data collection simulation and preprocessing workflow for logistics shipment records. It describes the structure of a 600-record synthetic dataset with shipment identifiers, delivery zone, distance, parcel weight, traffic, weather, vehicle type, service priority, delivery duration, transport cost, and an on-time indicator. The report explains likely quality problems such as missing categorical and numeric values, duplicate shipment identifiers, impossible measurements, inconsistent formats, and extreme values. Each issue is paired with a suitable treatment: duplicate checks, validation rules, median imputation for numeric fields, mode imputation for categorical fields, and interquartile-range flags for reviewing possible outliers. Outliers are reviewed rather than automatically deleted because long routes can be legitimate. The report also explains why scaling and categorical encoding may be needed for later models, and why transformations must be fitted on training data only to avoid data leakage. Python examples use pandas and scikit-learn to demonstrate the steps. The data is synthetic and intended for learning; it is not claimed to represent an actual logistics company's records. The report concludes that reliable preprocessing improves the credibility, reproducibility, and fairness of downstream analysis and operational decisions. The pipeline is intended to be repeatable: the same input and documented rules should produce the same cleaned output. The report emphasizes that data corrections should be traceable and that a suspicious value should be checked against its source whenever possible. It also describes the importance of separating training and test data before fitting transformations, which helps prevent overly optimistic model evaluation. These controls make the resulting analysis easier to explain and reproduce.
